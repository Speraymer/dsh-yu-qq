# QQ大肥鱼（dsh-yu-qq）

## 现在的行为

- 盯一个「目标会话」——**你自己选**，一般就是你平时和它聊天的那一间。
- `DSH → QQ`：它在某**一整轮的最后一句**说完，就把这句原文发到 QQ（走 QQ 后端的 `3000`）。
- `QQ → DSH`：插件每 4 秒轮询 QQ 后端（`get_friend_msg_history` / `get_group_msg_history`），
  发现你在 QQ 里新发的消息 → 转进目标会话，让它照常开一轮。
- 发/收都只走这个 QQ 后端的 HTTP 接口（默认 `127.0.0.1:3000`）。
- **图片两个方向都能传**：你在 QQ 里发的图会转给它看；它这一轮里发的图也会发到 QQ。
  收进来的图会在 `~/.dsh/qq-bridge-inbox/` 存一份，文字里带上路径。
  回发同一张图时用的是这份**原图** —— DSH 自己那份副本会被重新编码，GIF 动图会变静态 webp。
- **正文里写的 markdown 图也算**：它写 `![小肥鱼](_stickers/feiyu-test.webp)`（贴纸就是这么发的），
  会被读成本地图片发到 QQ，那串 markdown 不会露出来。相对路径按「图片根目录」找 —— **留空就行**，会自动用目标会话所在的那个工作区。
  ⚠️ 它到底能不能**看见**图，取决于那个会话用的模型：能看图的模型直接看，纯文本模型只会收到一句占位文字。
  🔒 发图有路径白名单：只认**目标会话的工作区**（它生成的图就落在这儿）、`qq-bridge-inbox/`、DSH 的 `attachments/ cache/ img/`；
  而且必须**真是图片**（查文件头，把别的文件改成 `.png` 也发不出去）。
- 安全默认：**总开关 = 关、试运行 = 开** —— 不手动打开，一句都不会真的发到 QQ。
- **群里不再每句话都接**（2026-10-23）：分两条路。
  · **被点名**——有人 `@` 它，或正文里提到「大肥鱼 / 鲸鱼娘 / 肥鱼」这类词（可在设置里改）→ **立刻接**，
    攒着的消息一起带进去；只歇 3 秒，防同一句话被后端重复返回时回两遍。
  · **没被点名**——有消息就攒着，**每 `群掷骰秒`（默认 60 秒）掷一次骰子**：默认 40% 起，
    没中就 +20%（加到 100 必然开口），开口后回到 40%。这套和主动搭话那个插件是同一个思路。
  · 攒着的消息最多 30 条，漏接太久也不会一口气灌进来；提示里也明确允许它只回 `SHUTUP`。
  · `at` = 只接被点名的；`always` = 老行为（每批都开一轮）。
- **会引用、会发表情**（2026-10-23）：
  · 转进去的每条群消息前面带 `[m:消息id]`；它回话时写 `[引用:那个id]` → QQ 那边变成「回复某条消息」。
  · `[表情:名字]` → 从「表情目录」（默认 `~/.dsh/qq-bridge-stickers/`）找同名图片当**大表情**发出去。
  · `[face:编号]` → OneBot 的 `face` 段，QQ 原生小表情。
  · Unicode emoji 直接写；提示会要求按语义挑选，没必要就不用，不再固定拿一个笑脸当句号。
  · 收到的 `mface` 大表情会按 QQ 给的语义名记住；只有 QQ 官方 HTTPS 素材地址才允许检索回发。本地同名表情图仍可照常使用。
- **会收文件（2026-10-23）**：你在 QQ 里发的 PDF / docx / zip 这类**文件**（不是图），
  会被下到本地 `~/.dsh/qq-bridge-inbox/文件/`，再把「哪个文件、多大、存在哪」写进转给它的文字里，
  它自己用文件工具去读。只收**你自己号**（`私聊QQ` / `指令QQ`）发的；群里别人发的只留一个文件名，不落盘。
  取字节的顺序：消息里带的下载链接 → 找后端再要一次（`get_group_file_url` / `get_private_file_url`）→ 后端已落地的临时文件（`get_file`）。
- **会发文件（2026-10-28）**：它正文里写 `[文件:文件名](路径)`（名字可省，`[文件](路径)` 也行），
  插件就把那个本机文件发到 QQ（私聊走 `upload_private_file`，群走 `upload_group_file`），标记本身不会露出来。
  先说话、再给东西；文件排在文字和图片后面。
  🔒 白名单比发图更严：只认**目标会话的工作区**（或设置里的「图片根目录」）里的文件，扩展名硬编码白名单 ——
  文档（pdf / doc / docx / xls / xlsx / ppt / pptx / odt / ods / odp）、纯文本（txt / md / csv / tsv）、
  压缩包（zip / 7z / rar）、图片、音视频（mp3 / wav / m4a / ogg / flac / mp4 / mov / mkv / webm）。
  `.json`、`.yaml`、`.env`、`.pem`、`.key`、数据库这类配置和密钥**一律发不出去**（根本不在表里）。
  一轮最多 3 个、单个默认 20MB（都能在设置里改）。后端读不到本地路径时，≤5MB 的文件会退回 `base64://` 再试一次。
- **会记住群友的表情**（2026-10-23）：群里收到的 QQ 表情自动记进 `~/.dsh/qq-bridge-stickers.json`
  （id / 安全素材地址、QQ 给的名字、用了几次、最近一次）；转进去的群消息开头会附一份「群里见过的表情」清单，
  它写 `[表情:给你一拳]` 就按 id 原样重发。名字直接取 QQ 自己的 `faceText`——那就是它的含义。
- **自动发现 + 开机补课（2026-10-23）**：手填一个群、一个私聊就够，剩下的靠 NapCat 自己报上来——
  `get_group_list` 里所有群都自动听，新群第一次来消息就自己建会话；`get_recent_contact` 里最近私信过的人
  各开一间独立会话（`私聊会话表`），回复只回给本人。
  每个群 / 每个人的「处理到哪一秒」落到 `~/.dsh/qq-bridge-state.json`；停机超过 2 分钟再开机，
  断档期间的消息按群 / 按人**合并成一条**补进来，标「离线补课」；**私聊会立即正常回复，群补课仍静音**。
  上限：每人最多 30 条、超过 48 小时的不补（都能在设置里改）。
  ⚠️ 自动收私聊开着 = 任何好友私信都会开一轮回复；不想被打扰就把这个开关关掉。

## 安装

> ⭐ 最省事的一条：把这个仓库的地址贴给你自己的 DSH，说「**帮我装这个插件**」。

打开 **设置 → 插件 → 安装**，把这一行填进去：

```
github:Speraymer/dsh-yu-qq
```

或者命令行（`--profile` 照你平时那个写，桌面端一般 `desktop`，网页端 `web`）：

```bash
dsh plugin --profile desktop add github:Speraymer/dsh-yu-qq
```

装完**重启一次 DSH**，然后进 **设置 → QQ大肥鱼**。

> 光装插件还不够：还得有一个 QQ 后端（默认 `127.0.0.1:3000`），见下面「它依赖什么」那一节。
> 同一份 DSH 配置中只启用一个 QQ 桥实例，避免重复收发。

### 装完起不来？先看这个

如果 DSH 弹「The application could not start」，错误里有 `Unexpected token '﻿'`、`is not valid JSON`、
`readProfileManifest` —— 那是 profile 的 `package.json` 被存成了 **UTF-8 带 BOM**。
**跟插件无关**：文件内容都是对的，只是开头多了三个看不见的字节，DSH 读它就崩。

**先找出来**（不同装法位置不一样，别猜 —— 真正的 profile 目录里同时有 `cordis.yml`、`cordis.patch.yml`、`package.json`；机器上别处那些同名的都不算）：

```powershell
Get-ChildItem C:\,D:\,E:\ -Directory -Filter profiles -Recurse -Depth 4 -ErrorAction SilentlyContinue |
  ForEach-Object {
    Get-ChildItem $_.FullName -Directory -ErrorAction SilentlyContinue | ForEach-Object {
      $p = Join-Path $_.FullName 'package.json'
      if ((Test-Path (Join-Path $_.FullName 'cordis.patch.yml')) -and (Test-Path $p)) {
        $b = [System.IO.File]::ReadAllBytes($p)
        $bom = ($b.Length -ge 3 -and $b[0] -eq 0xEF -and $b[1] -eq 0xBB -and $b[2] -eq 0xBF)
        "{0}   BOM={1}" -f $p, $bom
      }
    }
  }
```

**输出里 `BOM=True` 的那一行，就是要修的文件**（标准安装在 `C:\Users\<你>\.dsh\profiles\<档名>\package.json`）。
去掉 BOM（路径换成上面那一行）：

```powershell
$p = "把上面 BOM=True 那一行的路径粘到这里"
[System.IO.File]::WriteAllText($p, [System.IO.File]::ReadAllText($p), (New-Object System.Text.UTF8Encoding($false)))
```

然后重启 DSH 就好，**数据一点没丢**。

实在进不去时，那个错误框里的
**「Disable third-party plugins, back up profile patch, and restart」**
能先起来（它先备份再停插件），再一个个开回去定位。

> ⚠️ 手动改 profile 里的文件，一律存 **UTF-8 无 BOM**。让 AI 帮你改时，别让它用
> `Set-Content -Encoding UTF8` 或 `Out-File -Encoding utf8`（Windows 自带的这两个默认**带 BOM**），
> 用上面那行 .NET 的写法就不会。

## 配置（设置页里点就行，不用改文件）

**设置 → QQ大肥鱼**，从上到下：

| 项 | 默认 | 说明 |
| --- | --- | --- |
| 总开关 | 关 | 关着 = 一句都不发 |
| 试运行 | 开 | 开着只记账，不真发 |
| 目标会话 | （没选） | 下拉里选**你自己**要的那一间，**不用手填 id** |
| 转私聊 / 私聊 QQ 号 | 开 / 空 | 发到哪个私聊 |
| 转群 / 群号 | 关 / 空 | 发到哪个群；多个群用逗号分隔（例：1131553414,1041090263），每个群各自一间会话 |
| 收图（QQ → 它） | 开 | 你在 QQ 里发的图也转给它。文字里带本地备份路径 |
| 发图（它 → QQ） | 开 | 它这一轮里发的图也发到 QQ |
| 一条最多收几张 | 4 | 1–10，多出来的不转 |
| 单张最大（MB） | 5 | 超过就跳过，两个方向共用 |
| 收文件（QQ → 它） | 开 | 你发的文档类文件也转给它。只收你自己的号发的 |
| 一条最多收几个文件 | 3 | 1–10，多出来的只留名字 |
| 单个文件最大（MB） | 20 | 1–100，超过就不下 |
| 测试一句 | — | **真发**一条测试句到已填的私聊/群（绕过试运行） |
| 群接话 | auto | `auto` 点名立刻接 + 其余掷骰（默认）/ `always` 每批都接 / `at` 只接被点名的 |
| 群掷骰（秒） | 60 | 没被点名时，多久看一眼群、掷一次骰（10–600） |
| 群搭话概率（%） | 40 | 第一次掷骰的中签率 |
| 没中加多少（%） | 20 | 每没中一次往上加，加到 100 必然开口；开口后回到初始值 |
| 算「点名」的词 | 大肥鱼,鲸鱼娘,肥鱼 | 逗号分隔；正文里出现这些词也算在叫她 |
| 群会话 | 空 | 群里的话转进哪个会话；空 = 第一次收到消息时自动在「QQ会话目录」里建一个 |
| 私聊会话 | 空 | 私信转进哪个会话；空 = 同上 |
| QQ会话目录 | 空 | 自动建会话时用作 cwd；空 = `<文档>/deepseek-harness/QQ对话` |
| 自动收所有群 | 开 | 除了手填的群号，NapCat 里所有群都自动听；新群第一次来消息就自己开一间会话 |
| 自动收所有私聊 | 开 | 好友私信也收，每人一间独立会话，回复只回给本人（⚠️ 关掉才只听 `私聊QQ`） |
| 开机补课 | 开 | 停机超过 2 分钟再开机，把断档期间的消息合并成一条补进来；私聊正常回复，群补课静音 |
| 每个群/人最多补几条 | 30 | 1–200，补课文案里只放最近这么多条 |
| 超过多久不补（小时） | 48 | 1–336，停机太久就只补最近这一段 |
| 表情目录 | 空 | 大表情图放这儿，文件名就是 `[表情:名字]`；空 = `~/.dsh/qq-bridge-stickers/` |

配置文件落在 `%USERPROFILE%\.dsh\qq-bridge-config.json`（一般不用碰它）。

## 现在就能用的接口

- `GET /dsh-qq-bridge/state` —— 配置、日志、会话清单、以及「连着的 QQ 是哪个号/昵称」。
- `POST /dsh-qq-bridge/save` —— 存配置（body 里给要改的键）。
- `POST /dsh-qq-bridge/test-send` —— **真发**测试句（绕过试运行）。

```bash
node tests/宿主半边.mjs
node tests/群聊节流.mjs
node tests/网页半边.mjs
node --test tests/security.test.mjs
```

## 想让它发语音？（可选附加件）

主插件只管**文字**。想让 AI「念」出来的声音变成 QQ 语音条，`tools\语音\` 里放了整套：

| 文件 | 干什么 |
|---|---|
| `录语音.mjs` | 看门狗：盯着朗读桥，念的时候录音、录到就发 QQ |
| `录音回环.ps1` | 录音器（录系统声音回环，不要麦克风） |
| `朗读信号哨兵/` | Chrome 扩展：看到朗读桥面板的「🔊 点朗读」就通知看门狗开录 |

**两种发法，自己选**（双击 `启动-录语音.bat` 会让你输 1 或 2）：

| 模式 | 什么样 |
|---|---|
| **1 = 切断发** | 边录边发，念一段发一段（响应快，会连着几条） |
| **2 = 完整发** | 整段念完，把所有分段**拼成一条**再发 |

前提：Windows + 装了朗读桥（`dsh-tts-bridge`）+ QQ 后端支持发语音。
详细步骤见 [`tools/语音/README.md`](tools/语音/README.md)。

> 不装这一套也完全能用主插件。

## 它依赖什么：一个 QQ 后端（SnowLuma 或 NapCat，二选一）

插件本身**不碰 QQ 协议**，它只会说 **OneBot 11 的 HTTP**。所以你要在本机跑一个「QQ 接口」程序，
让插件通过 `http://127.0.0.1:3000` 跟它说话。

### 选哪个

| 后端 | 说明 |
|---|---|
| [**SnowLuma**](https://github.com/SnowLuma/SnowLuma) | **测过，能用**（本插件一直在用的就是这个）。 |
| [**NapCat**](https://github.com/NapNeko/NapCatQQ) | **也测过，能用**。自带网页后台（默认 `http://127.0.0.1:6099`）扫码登录，比自己配一端省事 |

### 插件实际用到的接口（换后端时照这个核对）

```
send_private_msg            发私聊
send_group_msg              发群消息
get_login_info              看登录的 QQ 是哪个（设置页显示"✓ 连着的 QQ"）
get_friend_msg_history      收私聊（QQ → DSH）
get_group_msg_history       收群消息（QQ → DSH）
get_group_file_url          群里发的文件：再要一次下载链接（收文件用）
get_private_file_url        私聊发的文件：同上
get_file                    后端已经落地的文件：直接拿本地路径（收文件用）
```

只要你的后端把这 9 个接口开在 HTTP 上，插件就能用（后三个缺了只影响收文件，其它照常）。

### 装 NapCat 的步骤

1. 从 [NapCat 的 Releases](https://github.com/NapNeko/NapCatQQ/releases) 下 Windows 版，解压到任意目录
2. 双击启动，它会弹一个**网页后台**（默认 `http://127.0.0.1:6099`）
3. 在网页里**扫码登录**你要用的 QQ 号
4. 确认 **HTTP 服务**开着、端口是 `3000`（不是的话，在插件设置里把「NapCat 地址」改成你的）
5. 回到 DSH → 设置 → QQ大肥鱼 → 点「测一下」，应该显示 `✓ 连着的 QQ：<昵称>（<号>）`

### 装 SnowLuma 的步骤

同样思路：跑起来 → 登录 QQ → **开启 OneBot 11 的 HTTP 服务** → 端口对上（或改插件里的地址）。
具体菜单名以它的文档为准：[SnowLuma 仓库](https://github.com/SnowLuma/SnowLuma)。

> 两个后端作者都实测过，接口对得上就能用。挑一个顺手的即可。

> ⚠️ 只有 **HTTP** 模式够用（插件不连 WebSocket）。开了 WS 但没开 HTTP 的话，插件连不上。

### 其它

- 桌面只留这个后端 + 本插件 + DSH。
- `/receive` 路由还留着，是想用别的方式（比如另一个程序）把 QQ 消息灌进来的备用入口，不依赖它也能跑。
